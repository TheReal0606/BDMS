# BDMS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Online bus GPS tracking: PHP/MySQL admin dashboard with a Waze-style live map, plus a Kotlin Android tracker APK paired by admin-issued code.

**Architecture:** Plain PHP 8 + PDO JSON API and server-rendered admin pages under `C:\xampp\htdocs\BDMS`. Admin map polls `api/buses.php` every 3s. Android foreground service posts batched GPS points to `api/location.php` with a Bearer token obtained from `api/pair.php`.

**Tech Stack:** PHP 8.2, MySQL (XAMPP), Leaflet 1.9.4 + CARTO dark tiles, vanilla JS; Kotlin, Android Gradle, Play Services Location, HttpURLConnection.

**Spec:** `docs/superpowers/specs/2026-10-29-bdms-design.md`

## Global Constraints

- No phone numbers used for identity; `contact_no` is optional display only.
- Every query on buses/locations/admins scoped by `company_id`.
- Passwords via `password_hash`/`password_verify`; all SQL via PDO prepared statements; output escaped with `htmlspecialchars`.
- Bus status: `moving` (speed > 2 km/h), `stopped`, `offline` (last_seen older than 120 s).
- Pairing code: 6 chars, uppercase A-Z / 2-9, unique.
- Tracker interval 5 s; upload batch max 100 points; app minSdk 26.
- Map default center Manila (14.5995, 120.9842), zoom 11.
- Server base URL configurable in `config.php` (PHP) and in the app's pairing screen.

## Review Focus

1. Duplicate/replayed offline batch (same `t` twice): inserted once, no error.
2. Invalid token or revoked bus on `location.php`: HTTP 401, app returns to pairing screen.
3. Lat/lng out of range or non-numeric: point rejected, rest of batch kept.
4. Admin of company A requests bus of company B (history, delete): 404.
5. Wrong/reused pairing code: clear error, no token issued.

### Task 3: Device API (pair + location)

**Files:**
- Create: `api/pair.php`, `api/location.php`

**Interfaces:**
- `POST api/pair.php` JSON `{code, device_name}` -> `{ok:true, token, bus:{id,name,plate}}`; 400/404 on bad/used code. Marks `pairing_used=1`, stores `api_token` (64 hex).
- `POST api/location.php` header `Authorization: Bearer <token>`, JSON `{points:[{lat,lng,speed,heading,battery,t}]}` (`t` = unix seconds) -> `{ok:true, accepted:n}`; 401 on unknown token. Uses `INSERT IGNORE` on UNIQUE(bus_id, recorded_at); updates `buses.last_*` from the newest accepted point only.
